# Введение в управление памятью

Как мы уже с вами знаем, `.NET` - это экосистема которая может очень умным образом управлять как процессорным временем, так и памятью. Для того чтобы понять как работает память в `.NET` нам нужно понимать что такое `Managed` и `Unmanaged` память.

Память состоит из двух частей:

- Stack
- Heap

Со `Stack`-ом вы уже знакомы еще со времен С++, в этой области хранится все, начиная от переменных, заканчивая информацией о вызове методов. `Stack` - это область памяти, которая выделяется во время компиляции программы. Раньше вы думали что он один у нас в программе, но на самом деле это не так.

В C# при запуске программы создается `Main` метод в классе `Program` и работает это все в `Main Thread`. Помимо `Main Thread` у нас создается еще несколько потоков в зависимости от типа проекта и его размера. Вот пример выводе информации о потоках в обычной консольной программе:

```csharp
using System.Diagnostics;

var threads = Process.GetCurrentProcess().Threads;

Console.WriteLine($"Total threads: {threads.Count}");
foreach (ProcessThread thread in threads)
{
    Console.WriteLine($"Id: {thread.Id}\tThreadState: {thread.ThreadState}");
}

```

Как вы видите у нас есть 11 потоков, один из которых `Main Thread`, а остальные потоки создаются в зависимости от того что мы делаем в программе.

`Stack` каждого потока весит 1 мегабайт, и если у вас есть 10 потоков, то у вас уже 10 мегабайт памяти занято.

Давайте поговорим подробно про `Managed` и `Unmanaged` память.

`Managed` память - это память которая управляется CLR-ом.
`Unmanaged` память - это память которая управляется программистом. За это отвечает ключевое слово `unsafe`(работала с указатеялями) и работа с сетевыми сокетами.

```csharp

unsafe
{
    int length = 10;

    // Выделяем память в куче для массива из 10 элементов типа int
    int* arrayPtr = (int*)Marshal.AllocHGlobal(length * sizeof(int));

    try
    {
        // Инициализируем массив
        for (int i = 0; i < length; i++)
        {
            arrayPtr[i] = i + 1;
        }

        // Вывод значений массива
        Console.WriteLine("Array values in heap:");
        for (int i = 0; i < length; i++)
        {
            Console.WriteLine($"Element {i}: {arrayPtr[i]}");
        }
    }
    finally
    {
        // Освобождаем выделенную память
        Marshal.FreeHGlobal((IntPtr)arrayPtr);
    }
}

```

Возможно вы удивитесь, но `Heap` в `.NET` работает быстрее чем `Heap` в `C++`.

![Вот пример работы `Heap` в `.NET`](https://tooslowexception.com/wp-content/uploads/2019/08/gcposter05.png)

`Stack` как я уже сказал выделяется на каждый поток отдельно. Весит 1мб и выделяется при
компиляции. Там хранятся переменные, информация о вызове методов, значимые типы данных.

`Heap` - это динамическая область памяти которая бывает как `Managed` так и `Unmanaged`.
`Managed` память управляется CLR-ом, а `Unmanaged` память управляется программистом.
Пример с `Unmanaged` памятью я вам показал выше.

## Managed Heap

Сам по себе он делится на три части(поколения):

- Generation 0
- Generation 1
- Generation 2

Каждое поколение отлитчается от предыдущего тем, что в самом первом хранятся мелкие и часто
используемые данные, к которым нужен быстрый доступ. Например, в следующее поколение
могут попасть как элементы которые стали весить больше, так и элементы которые стали
редко использоваться.

Для того чтобы сделать переход в `CLR` есть такая утилита как `GC` - `Garbage Collector`.

Его называют сборщиком мусора, но на самом деле его основная работа не просто убирать
неиспользуемые данные, а еще и переносить данные **_с одного поколения в другое_**.

### SOH - Small Object Heap

Это область памяти в которой хранятся мелкие объекты. Внутри него есть 3 поколения:

- Generation 0
- Generation 1
- Generation 2

### LOH - Large Object Heap

Это область памяти в которой хранятся большие объекты. Внутри него хранятся статические
данные, данные с БД и т.д.

LOH не компактизируется при сборке мусора, чтобы избежать затрат на перемещение больших объектов

### POH - Pinned Object Heap

Это область памяти в которой хранятся объекты которые нельзя перемещать. Например, если
у вас есть объект который использется при генерации `GUI`, то он хранится там. К примеру
информация о длине и ширине окна и т.д.

### FOH - Frozen Object Heap

FOH (Frozen Object Heap) — Куча замороженных объектов

- Введена в .NET 6.
- Хранит неизменяемые объекты (immutable objects), которые не участвуют в сборке мусора.
- Обеспечивает оптимизацию производительности и памяти.

Следующий момент который нас должен интеремовать это как происходит удаление, то есть `Garbage Collection`.
и как закрываются потоки.

## Garbage Collection

`Garbage Collection` - это процесс удаления объектов которые больше не используются. Не нужно думать что
к примеру у вас есть string который не используется и он удалится как было в `C++`. Когда какое-то
поколение заполняется, то происходит сборка мусора.

Сборка мусора происходит в 3 этапа:
- Mark
- Sweep
- Compact

### Mark

Он помечает объекты которые нужно удалить. Например, если у вас есть объект который ссылается на другой
объект, то он помечает оба объекта.

### Sweep

Он удаляет объекты которые были помечены на предыдущем этапе.

### Compact

Он перемещает объекты которые остались в куче, чтобы уменьшить фрагментацию памяти.
