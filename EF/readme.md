# Что такое EF Core ?

`EF Core` - это фреймворк для работы с базами данных, который считается `ORM` (Object Relational Mapping). С помощью него мы можем полностью отказаться от написания SQL запросов и работать с базой данных, как с обычными объектами с помощью `LINQ`.

# Почему его называют Framework ?

Мы уже с вами говорили о различиях между framework и library, но давайте уточним некоторые тонкости. Библиотека - это инструмент который дает мне готовые классы, структуры, методы и т.д. По сути библиотека решает какие-то проблемы. Например библиотека `BCrypt`, позволяет нам хешировать пароли. Библиотека `Microsoft.Data.SqlClient` позволяет подключаться к базе данных MS SQL Server. То есть у них есть конкретные задачи, где мы от них не зависим.

В случае с `framework`, все не так просто. `framework` - это более комплексный инструмент, который может состоять из нескольких библиотек. Но это не все. Самое главное, что `framework` сковывает нас своей возможностью и определяет какова будет архитектура нашего приложения. Например, 'NET.Core`- это`framework`, который определяет какие у нас будут библиотеки, какие у нас поддерживаются языки, какого типа приложения мы можем создавать и т.д.

# Какие преимущества у EF Core ?

- Простота использования
- Возможность работать с базой данных, как с обычными объектами
- Поддержка LINQ
- Поддержка множества баз данных
- Возможность использовать миграции
- Отсутствие необходимости писать SQL запросы
- Масштабируемость
- Возможность использовать в любом типе приложения

# Типы подходов к работе с EF Core

Существует два основных подхода к работе с EF Core:

- Database First
- Code First

На прошлом уроке, мы с вами уже познакомились с `Database First`, когда мы создавали модель данных на основе существующей базы данных. Этот проект мы продолжим позже. С сегодняшнего дня будем писать код с нуля, используя подход `Code First`.

# DbSet

`DbSet` - это тип данных, который представляет собой таблицу в базе данных. Все операции с базой данных мы будем делать через `DbSet`.

# Migrations

Хорошим примером объянения этому будет транзакции в SQL, которые я мог подтверждать или откатывать. Или же принцип работы Git технологии где я делаю `commit`-ы по которым я могу перемещаться. Грубо говоря если вы сделаете изменение которое сломает базу данных, то вы сможете откатить это изменение.

для того чтобы создать миграцию, нужно выполнить команду:

```bash
dotnet ef migrations add <name>
```

для того чтобы применить миграцию, нужно выполнить команду:

```bash
dotnet ef database update
```

# Типы подгрузок
- Lazy Loading
- Explicit Loading
- Eager Loading

### Lazy Loading

Это устаревший тип подгрузки, так как он очень сильно грузит память и делает `Join`-ы неявно, что очень сильно убивает нашу производительность. Особенно если наша БД сильно нормализована.

### Explicit Loading

Это тип подгрузки, который позволяет нам явно указать какие данные мы хотим загрузить. Это делается с помощью метода `Include`.

```csharp
var cars = context.Cars.Include(c => c.Owner).ToList();
```

### Eager Loading

Это тип подгрузки, который позволяет нам загрузить все данные сразу. Это делается с помощью метода `Load`.

```csharp
context.Entry(car).Reference(c => c.Owner).Load();
```

Тут большинство студентов путаются при работе с `Include` и `Load`. `Include` - это метод который позволяет нам загрузить данные сразу, а `Load` - это метод который позволяет нам загрузить данные по требованию. 

Принцип их работы такой, если у вас в таблице `Cars` есть внешний ключ на таблицу `Owners`, то при использовании `Include` мы сразу загрузим все данные из таблицы `Owners`, а при использовании `Load` мы загрузим данные только тогда, когда обратимся к ним.

По мере работы я покажу вам какой подход когда следует исользовать. Но в целом, `Lazy Loading` - это плохой подход, который нужно избегать. `Explicit Loading` и `Eager Loading` - это хорошие подходы, которые нужно использовать в зависимости от задачи.
