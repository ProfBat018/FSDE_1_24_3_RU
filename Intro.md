# Паттерны проектирования

Это список готовых шаблонов для решения уже давно известных задач. 
Учитывая что в современном мире мы редко изобратеам велосипед, данные паттерны больше помогают вам понять то, как работают те или иные механизмы, которые используются в библиотеках или же фреймворках.

Паттерны делятся на 3 категории:
- Порождающие (Creational)
- Структурные (Structural)
- Поведенческие (Behavioral)

В общем у нас есть 23 паттерна из которые есть часто используемые и редко используемые. 

[Вот список всех паттернов проектирования](https://refactoring.guru/ru/design-patterns/catalog)


# S.O.L.I.D. (Принципы SOLID)

- S - Single Responsibility Principle (Принцип единственной ответственности)
- O - Open/Closed Principle (Принцип открытости/закрытости)
- L - Liskov Substitution Principle (Принцип подстановки Барбары Лисков)
- I - Interface Segregation Principle (Принцип разделения интерфейса)
- D - Dependency Inversion Principle (Принцип инверсии зависимостей)

# Оставшиеся аббревиатуры
- GRASP - General Responsibility Assignment Software Patterns (Общие шаблоны назначения ответственности программного обеспечения)
- DRY - Don't Repeat Yourself (Не повторяйся)
- KISS - Keep It Simple, Stupid (Сделай это просто, глупо)
- YAGNI - You Aren't Gonna Need It (Тебе это не нужно)
