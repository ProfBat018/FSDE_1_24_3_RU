# MicroORM vs ORM

Начнем с того что  `ORM` - это `Object-Relational Mapping`,
а `MicroORM` - это `Micro Object-Relational Mapping`.

Суть этих подходов в том, что мы соединяем наши классы и наши 
таблицы друг с другом. Разница между ними только в том, что
`ORM` - дает большой набор инструментов для работы, а `MicroORM`
предоставляет минимальный набор инструментов для работы.

Запомните, у каждого из них есть свои плюсы и минусы. 


# Что такое ADO.NET

`ADO.NET` - это API для работы с базой данных `MS SQL Server`.

Напоминаю, что `API` - это способ взаимодействия. 

Для работы всей этой системы есть такой драйвер как `ODBC` - 
Open Database Connectivity. Он позволяет вам работать с
разными базами данных, но в нашем случае мы будем использовать
`MS SQL Server`. Что очень интресно, `ADO.NET` является самым низкоуровневым
подходом для работы с базами данных, что делает написание кода на нем достаточно
сложным, но при этом все другие технологии используют его для работы.

В нем есть два способа работы: 
1. Connected Mode - где вы постоянно подключены к базе данных и все ваши изменения
сразу же отражаются в базе данных.
2. Disconnected Mode - где вы подключаетесь к базе данных, забираете данные, 
записываете их в опративную память, а потом вносите изменения и синхронизируете
их с базой данных при надобности. 

1 способ надежный для ввода, а 2 способ надежный для вывода. Про это 
мы будем говорить уже во время EF Core. 

`ADO.NET` не является `ORM` или же `MicroORM`, это просто набор классов
для выполнения запросов к базе данных.

# Что такое Dapper

`Dapper` - это `MicroORM` для работы с базой данных. Он предоставляет
набор инструментов для удобной работы с БД. Самая главная его особенность
в том, что мы можем сделать связку класса и таблицы. Dapper тоже работает
с `ADO.NET` под капотом, при этом он очень быстрый что делает его одним из 
самыз востребованных решений для работы с `SQL` для `.NET`.

Для его работы нам понадобится установить два пакета:

1. `Microsoft.Data.SqlClient`
2. `Dapper`

# Что такое Entity Framework

`Entity Framework` - это `ORM` для работы с базой данных. В нем есть очень много
всего. Коротко говоря при работе с ним нам не придется писать `SQL` запросы,
взамен мы будем использовать `LINQ` запросы. Подробнее про него мы поговорим в будущем.

## SplitOn 

`SplitOn` - это метод, который позволяет нам разделить наш результат на два объекта.
Пример будет в `Part9`

```csharp
var categories = connection.Query<Category, Category, Category>(sqlQuery, (category, parentcategory) =>
{
    category.ParentCategory = parentcategory;
    return category;
}, splitOn: "Name");

foreach (var category in categories)
{
    Console.WriteLine($"{category.Name} - {category.ParentCategory.Name}"); 
}


```

В данной части кода вы можетк увидеть что я принмаю в Generic сразу три `Category`. Так совпало что я взял достаточно 
сложный пример где я соединяют таблицу с самим собой, но в целом это достаточно легкий метод. Его принцип работы прост.

Первый параметр - это первая табллица. Второй параметр - это вторая таблица. Третий параметр - это результат, который 
должен вернуться. В моем слусае я `Category` соединяю с `Category` и возвращаю `Category`. Из-за этого у меня 
получилось небольшое дублирование, но в целом это правильно так и должно быть. 

Первый параметр в методе `Query` - это ваш sql запрос. Второй параметр это функция, которая должна вернуть вам 
в результате объект с тем типом который вы указали в третьем параметре. В нашей лямбде мы двумя аргументами принимаем
две категории и возвращаем одну в теле функции.

`SplitOn` - это параметр, который позволяет нам разделить наш результат на два объекта. В данном случае я указал что
разделение должно происходить по полю `Name`. Потому что у меня есть Две категории и у них есть одинаковое поле `Name`.
Таким образом я могу разделить результат на два объекта.
