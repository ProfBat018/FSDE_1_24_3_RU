## Что такое HTTP ? 

HTTP (Hypertext Transfer Protocol) - это протокол передачи данных, который является протоколом 7-го уровня модели OSI и используется для передачи данных по сети. Он является основоположником WEB-технологий и используется для передачи гипертекстовых документов, таких как HTML, CSS, JavaScript и других файлов. HTTP работает по модели клиент-сервер, где клиент (обычно это веб-браузер) отправляет запросы на сервер, а сервер отвечает на эти запросы. Его создал Тим Бернерс-Ли в 1989 году. Разные версии HTTP использую разные порты и транспортные протоколы, но об этом позже. 

Мы уже с вами прошли FTP, но чтобы у вас не было путаницы в голове я объясню как происходит скачивание файлов по FTP и HTTP. 

В случае с FTP, нам было бы сложно скачивать файлы с помощью ссылок, так как ему нужно конкретно сказать метод запроса, то есть DownloadFile. В случае с HTTP, любая ссылка которую вы открываете в браузере является `GET` запросом, который как раз таки нам и нужен. Более того, вы должны учесть то, что FTP открывает разные соединения для передачи данных и управления, а HTTP использует одно соединение для передачи данных. Это позволяет HTTP быть более эффективным и быстрым, чем FTP. Давайте подробнее разберем как работает HTTP. 


## Как работает HTTP ? 

`HTTP` работает по модели клиент-сервер, где клиент (обычно это веб-браузер) отправляет запросы на сервер, а сервер отвечает на эти запросы. Самый привычный формат общения в браузере это `application/json`, но на самом деле это не единственный формат. HTTP поддерживает множество форматов, таких как `text/html`, `application/xml`, `image/jpeg` и многие другие. С `json`, `xml`, `html` вы уже знакомы. 

Сам по себе HTTP это всего лишь протокол, который определяет правила обмена данными между клиентом и сервером. Он не определяет, как именно должны выглядеть данные, которые передаются между клиентом и сервером. Это делает его очень гибким и универсальным.


## Методы HTTP 
- `GET` - используется для получения данных с сервера. Например, когда вы открываете веб-страницу в браузере, браузер отправляет `GET` запрос на сервер, чтобы получить HTML-код страницы.
- `POST` - используется для отправки данных на сервер. Например, когда вы заполняете форму на веб-странице и нажимаете кнопку "Отправить", браузер отправляет `POST` запрос на сервер с данными формы.
- `PUT` - используется для обновления данных на сервере. Например, когда вы редактируете статью на сайте и нажимаете кнопку "Сохранить", браузер отправляет `PUT` запрос на сервер с обновленными данными статьи.
- `DELETE` - используется для удаления данных на сервере. Например, когда вы удаляете статью на сайте, браузер отправляет `DELETE` запрос на сервер с идентификатором статьи, которую нужно удалить.


## Статусы HTTP 

Есть коды ошибок которые начинаются на `1xx`, `2xx`, `3xx`, `4xx`, `5xx`.

- `1xx` - информационные коды, которые указывают на то, что запрос был принят и обрабатывается. Например, код `100 Continue` указывает на то, что сервер готов продолжать обработку запроса.
- `2xx` - успешные коды, которые указывают на то, что запрос был успешно обработан. Например, код `200 OK` указывает на то, что запрос был успешно обработан и сервер вернул ответ.
- `3xx` - коды перенаправления, которые указывают на то, что клиент должен выполнить дополнительный запрос для получения ответа. Например, код `301 Moved Permanently` указывает на то, что запрашиваемый ресурс был перемещен на другой URL.
- `4xx` - коды ошибок клиента, которые указывают на то, что запрос был некорректным. Например, код `404 Not Found` указывает на то, что запрашиваемый ресурс не найден на сервере.
- `5xx` - коды ошибок сервера, которые указывают на то, что сервер не смог обработать запрос. Например, код `500 Internal Server Error` указывает на то, что сервер столкнулся с ошибкой при обработке запроса.

## Содержание HTTP-запроса

HTTP-запрос состоит из трех частей: строки запроса, заголовков и тела запроса.
- Строка запроса содержит метод HTTP, URL и версию протокола. Например, строка запроса `GET /index.html HTTP/1.1` указывает на то, что клиент отправляет `GET` запрос на сервер для получения файла `index.html` с использованием версии протокола `HTTP/1.1`.

![](https://encrypted-tbn0.gstatic.com/images?q=tbn:ANd9GcROdhT8umDzN4T6pN2X6IaCA7st9RUmfBALJQ&s)

- Тип запроса - `GET`, `POST`, `PUT`, `DELETE`
- Путь запроса - `/index.html`
- Версия протокола - `HTTP/1.1`
- Хост - `Host: www.example.com`
- Accept-Language - `Accept-Language: en-US`

- Заголовки содержат дополнительную информацию о запросе, такую как тип контента, язык, кодировка и другие параметры. Например, заголовок `Content-Type: application/json` указывает на то, что тело запроса содержит данные в формате JSON.
- Тело запроса содержит данные, которые отправляются на сервер. Например, при отправке формы на веб-странице тело запроса может содержать данные формы в формате `application/x-www-form-urlencoded` или `multipart/form-data`.
- Заголовок `User-Agent` указывает на то, какой браузер или клиент отправил запрос. Например, заголовок `User-Agent: Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/58.0.3029.110 Safari/537.3` указывает на то, что запрос был отправлен браузером Google Chrome на операционной системе Windows 10.
- Заголовок `Accept` указывает на то, какие типы контента клиент может обрабатывать. Например, заголовок `Accept: application/json` указывает на то, что клиент может обрабатывать данные в формате JSON.


## Версии HTTP 

Самой первой версией был `HTTP/1.1`, который был выпущен в 1999 году. Тут для request и для response открываются разные соединения. До сих пор много сайтов используют эту версию. 
В 2015 году была выпущена версия `HTTP/2`, которая использует одно соединение для передачи данных и управления. Это позволяет HTTP/2 быть более эффективным и быстрым, чем HTTP/1.1. 
В 2020 году была выпущена версия `HTTP/3`, которая использует QUIC (Quick UDP Internet Connections) вместо TCP (Transmission Control Protocol) для передачи данных. Это позволяет HTTP/3 быть еще более эффективным и быстрым, чем HTTP/2.

То есть HTTP/1.1 использует TCP, HTTP/2 использует TCP а HTTP/3 использует QUIC, который является оберткой над UDP.
При этом  учтите что HTTP/3 еще не поддерживается всеми браузерами и серверами, поэтому многие сайты по-прежнему используют HTTP/2 или HTTP/1.1.


## Domain Name System (DNS)

DNS (Domain Name System) - это система, которая переводит доменные имена в IP-адреса. Обычно у вашего провайдера есть свой DNS сервер, который вы используете. Этот сервер хранит в себе информацию о друних `nameserver`-ах. Nameserver - это сервер, который хранит информацию о доменах. К примеру вы можете купить один и тот же домен в раных компаниях за разные деньги. При этом у каждого из них будет свой nameserver. У кого-то он будет знаменитый, а у кого-то нет. 

То есть если сайт первый раз долго грузится, это значит что в вашем DNS сервере нет информации о этом сайте и он будет искать его в других DNS серверах. Конечно же не каждый сайт который вы открываете сразу будет обращаться к DNS провайдера. В вашем домашнем модеме есть свой кеш, который хранит информацию о сайтах которые вы открывали. У каждого по факту разные доменные имена, купленные в одной компании могут иметь один и тот же nameserver. Это говорит о том что у них один и тот же провайдер. 

## SSL (Secure Sockets Layer) 

SSL (Secure Sockets Layer) - это протокол, который обеспечивает безопасное соединение между клиентом и сервером. Он шифрует данные, которые передаются между клиентом и сервером, чтобы предотвратить их перехват и изменение. SSL был разработан компанией Netscape в 1994 году и стал стандартом для обеспечения безопасности в интернете. 

P.S. Если что `netscape` это первое им 

SSL использует как симметричное, так и асимметричное шифрование для обеспечения безопасной передачи данных:

- Асимметричное шифрование используется на начальном этапе (handshake), когда клиент и сервер обмениваются ключами. Здесь используются два ключа: публичный и приватный. Публичный ключ может быть открыт для всех, но только приватный ключ может расшифровать сообщение. Это как если бы вы положили сообщение в шкатулку и закрыли её на замок (публичный ключ), а открыть её можно только приватным ключом (который есть только у получателя).
- Симметричное шифрование используется после установки безопасного соединения — и клиент, и сервер используют один и тот же секретный ключ для шифрования и дешифровки данных. Это быстрее, чем асимметричное шифрование, поэтому оно применяется для основного обмена данными.

Процесс работы SSL:
1. Клиент (например, браузер) отправляет запрос на сервер с указанием, что хочет установить защищённое соединение.
2. Сервер отправляет цифровой сертификат (обычно в формате X.509), который содержит публичный ключ и информацию о владельце.
3. Клиент проверяет подлинность сертификата через доверенные центры сертификации (CA).
4. Если сертификат валиден, клиент генерирует секретный симметричный ключ (session key), шифрует его публичным ключом сервера и отправляет серверу.
5. Сервер дешифрует session key с помощью своего приватного ключа.
6. С этого момента все данные шифруются симметричным ключом, что обеспечивает безопасность и производительность.

Важно отличать **шифрование (encryption)** от **кодирования (encoding)**:
- **Кодирование** — это преобразование данных в другой формат для совместимости или хранения. Пример: Base64, URL-кодирование. Кодированные данные легко раскодировать и они не предназначены для защиты.
- **Шифрование** — это преобразование данных с целью скрыть их содержимое от посторонних. Только тот, кто обладает нужным ключом, может расшифровать данные.

Именно SSL/TLS делают возможным безопасный интернет, обеспечивая конфиденциальность (через шифрование), подлинность (через сертификаты) и целостность (через MAC).

## TLS (Transport Layer Security)

TLS (Transport Layer Security) - это протокол, который работает на уровне траспорта с вашего браузера. Он работает поверх SSL и являктся по факту частью `HTTPS`. есть три версии TLS: TLS 1.0, TLS 1.1 и TLS 1.2. TLS 1.0 был выпущен в 1999 году и является устаревшим протоколом, который больше не рекомендуется использовать. TLS 1.1 был выпущен в 2006 году и также является устаревшим протоколом. TLS 1.2 был выпущен в 2008 году и является самым распространенным протоколом на данный момент.
TLS 1.3 был выпущен в 2018 году и является самым новым протоколом, который улучшает безопасность и производительность по сравнению с предыдущими версиями. TLS 1.3 использует более современные алгоритмы шифрования и упрощает процесс установки защищенного соединения, что делает его более быстрым и безопасным.

## Хеширование паролей

Начнем с того что хеширование это не шифрование, а односторонняя функиця которая кодирует данные безвозвратно. То есть если вы захешируете данные, вы не сможете их расхешировать. Пример очень простой, происходит большое количество математичемских операций над данными. Даже зная алгоритм вы не сможете расхешировать данные, так как в обычной 64-х битной системе у вас будет 2^64 возможных комбинаций. В секундах даже солнечная система не проживет столько времени. 

Допустим если мы возьмем `SHA` - Secure Hash Algorithm, то он будет работать по следующему принципу.
1. Вы берете данные и разбиваете их на блоки по 512 бит.
2. Каждый блок обрабатывается с помощью функции, которая использует ключ и алгоритм шифрования.
3. Результат обработки каждого блока объединяется с результатом предыдущего блока.
4. В конце получается хеш-значение, которое является уникальным представлением исходных данных.

Представьте что пройдя n операций вы получили хеш длиной в 512 бит и вы знаете что для его хеширования использовался алгоритм SHA512. Если вы хотите расшифровать его, вам нужно будет пройти все возможные комбинации. К примеру одна и та же стадия расхеширования может быть использвана для разных данных. Представьте к примеру что 6 стадия хещирования у вас может совпасть с 1_000_000 слов которые вы можете использовать, тогда вам  нужно будет пройти 1_000_000 операций для данной стадии. 

Что касается шифрования, то хеширования недосаточно. Потому что можете сделать метод подбора или `Broot Force` атака. Вы делаете предположение пароля и хешируете его. Затем вы сравниваете его с хешем который у вас есть. Если они совпадают, значит вы угадали пароль. На GitHub есть много репозиториев с хешами паролей, которые вы можете использовать для подбора. 

Для того чтобы этого избежать, вам нужно использовать `Salt` 

То есть вы должны добавить к вашему хешу случайную строку по алгоритму который будете знать только вы. Много где пишется неправильно и говорится что соль нужно добавлять к паролю, но на самом деле соль добавляется к хешу. Только вы знаете как отделить соль от хеша.

## Пример HTTP-запроса на C#

Давайте сделаем два вида запроса с помощью `HttpClient` и `WebClient`. `WebClient` это устаревший класс, который не рекомендуется использовать, но я вам его покажу так как он есть у нас в программе. 

Пример будет на бахе `api` `openweathermap.org`, который вы можете использовать для получения погоды. 

```csharp

using System;
using System.Net;
using System.Net.Http;

var client = new WebClient();

var url = "https://api.openweathermap.org/data/2.5/weather?q=London&appid=YOUR_API_KEY";
var response = client.DownloadString(url);
Console.WriteLine(response);
```

Как вы видите все очень просто. Вы создаете объект `WebClient`, затем вызываете метод `DownloadString` и передаете ему URL. В результате вы получаете ответ от сервера в виде строки, который являеся JSON-объектом. 
Вы можете без проблем сделать десериализацию этого объекта в класс. Но еще раз говорю что `WebClient` устарел и его не рекомендуется использовать. 

Теперь давайте сделаем то же самое с помощью `HttpClient`. 
```csharp

using System;
using System.Net.Http;

var client = new HttpClient();

var url = "https://api.openweathermap.org/data/2.5/weather?q=London&appid=YOUR_API_KEY";

var response = await client.GetAsync(url);

if (response.IsSuccessStatusCode)
{
    var content = await response.Content.ReadAsStringAsync();
    Console.WriteLine(content);
}
else
{
    Console.WriteLine($"Error: {response.StatusCode}");
}
```
В этом примере мы создаем объект `HttpClient`, затем вызываем метод `GetAsync` и передаем ему URL. В результате мы получаем ответ от сервера в виде объекта `HttpResponseMessage`. Затем мы проверяем статус ответа и если он успешный, то читаем содержимое ответа с помощью метода `ReadAsStringAsync`.

Тут есть еще один более предпочтительный способ, который позволяет вам использовать `using` и не создавать объект `HttpClient` каждый раз. 
```csharp

using System;
using System.Net.Http;

using var client = new HttpClient();

var url = "https://api.openweathermap.org/data/2.5/weather?q=London&appid=YOUR_API_KEY";

var response = await client.GetAsync(url);

if (response.IsSuccessStatusCode)
{
    var content = await response.Content.ReadAsStringAsync();
    Console.WriteLine(content);
}
else
{
    Console.WriteLine($"Error: {response.StatusCode}");
}
```

Следующий пример уже с использованием `httprequestmessage`. 
```csharp

using System;
using System.Net.Http;

using var client = new HttpClient();

var url = "https://api.openweathermap.org/data/2.5/weather?q=London&appid=YOUR_API_KEY";

var httpRequestMessage = new HttpRequestMessage()
{
    Method = HttpMethod.Get,
    RequestUri = new Uri(url),
    Headers =
    {
        { "Accept", "application/json"}
    }

};

var response = await client.SendAsync(httpRequestMessage); 

if (response.IsSuccessStatusCode)
{
    var content = await response.Content.ReadAsStringAsync();
    Console.WriteLine(content);
}
else
{
    Console.WriteLine($"Error: {response.StatusCode}");
}
```

В этом примере мы создаем объект `HttpRequestMessage`, устанавливаем метод запроса, URL и заголовки. Затем мы отправляем запрос с помощью метода `SendAsync` объекта `HttpClient`. Это самый предпочтительный способ отправки запросов, так как он позволяет вам настраивать запрос более гибко.
